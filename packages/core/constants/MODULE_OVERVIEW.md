# 常量模块概览

## 模块定位

`deepsearch/constants` 汇集系统、业务、事件相关的常量定义，确保仓库内各层共享统一枚举、默认值与编码约束。模块按语义拆分为
`system.py`、`business.py`、`events.py`、`defaults.py`，并在 `__init__.py` 中聚合导出热点常量。

## 子模块说明

- `system.py`：维护系统级默认设置（编码、超时、重试、线程池/队列规模、端口、缓存 TTL 等）以及错误码区段，供运行时、基础设施和监控模块调用。
- `business.py`：定义交易相关枚举，包括订单状态、交易所列表（覆盖国内外主要市场）、订单方向/类型、持仓方向以及字段长度、价格/数量范围等约束。
- `events.py`：集中声明事件总线使用的事件名，例如 `_SYSTEM_READY_`、`TICK`、`ORDER`、`TRADE` 等，避免硬编码字符串导致的订阅/发布错误。
- `defaults.py`：描述应用默认元信息、日志目录、日志轮转策略等。模块加载时会调用 `ensure_directories()`
  自动创建日志目录，保证观测模块初始化前的目录存在。

## 使用要点

- 常量使用全局 `APP_NAME`、`LOG_DIR` 等供配置和日志模块访问，确保命名一致。
- 错误码按照功能区间划分（系统 1000-1999、事件 2000-2999、存储 3000-3999 等），便于统一处理与监控告警。
- 在交易流程中统一引用 `Status`, `Exchange`, `ORDER_TYPE_*` 等枚举，杜绝魔法字符串。
- 默认端口、缓冲区大小等常量为运行时组件提供基线值，实际部署可通过配置覆盖。

## 扩展建议

- 新增事件或交易相关枚举时，应在对应文件补充注释并保持命名风格一致。
- 若引入新的错误类别，按照现有区间划分添加新的常量以便日志和监控模块分类处理。
