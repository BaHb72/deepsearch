# 微信小程序接入建设计划

## 背景与目标
- 小程序作为轻量级触达渠道，可承载行情速览、预警订阅和账号管理的核心能力。
- 需在不破坏既有 AmazingData 优先策略的前提下，实现对领域服务的受控访问。
- 项目目标：在 3 个迭代内完成 MVP（行情查询 + 简版预警订阅），并为后续深度运营留出扩展空间。

## 范围与约束
- **体系边界**：小程序前端仅通过开放 API 网关访问，禁止直接访问领域或基础设施层。
- **架构规则**：遵循 ports/adapters，相关 Protocol 置于 `ports/`, 实现放入 `adapters/` 或 `infrastructure/webui` 新增模块。
- **数据约束**：继续以 AmazingData 数据为主源，所有跨端数据结构使用 `dataclasses`/`TypedDict` 定义，严禁向领域层透传 `dict[str, Any]`。
- **账号安全**：必须沿用现有鉴权链路（JWT + 策略校验），并补充微信 OpenID/UnionID 映射机制。
- **配置管理**：新增配置写入 `settings.<env>.yaml` 衍生文件，不改动默认生产配置前需完成灰度验证。

## 里程碑拆解

### 阶段一：方案调研（1 周）
- 调研微信开放平台限制：登录态、服务器域名白名单、消息推送限制。
- 盘点现有 WebUI API 可直接复用的能力，识别需新增的端口。
- 输出《小程序接入技术评估》初稿，明确依赖列表、风险与回滚策略。

### 阶段二：底座搭建（1.5 周）
- **端口定义**：在 `ports/wechat/` 目录（新建）定义会话管理、模板消息推送等 Protocol。
- **适配器雏形**：在 `adapters/wechat_miniapp/` 实现微信 SDK 对接，封装登录态校验、token 换取与消息发送。
- **配置与密钥管理**：扩展 `settings.dev.miniapp.yaml` 示例，使用占位符存放 AppID、AppSecret，禁止写入真实密钥。
- **API 网关**：在 `deepsearch/webui/api` 内新建 `miniapp` 子路由，暴露登录、行情查询、订阅管理等接口骨架。
- **文档同步**：补充 `docs/api/FRONTEND_API_REGISTRY.md` 和 `docs/architecture` 中关于渠道拓扑的更新。

### 阶段三：领域对接与数据建模（2 周）
- 为小程序侧交互设计专用 DTO，例如 `MiniAppQuoteRequest`, `MiniAppWatchList`.
- 扩展领域服务：通过既有服务编排，实现小程序友好的精简视图（如聚合实时价与涨跌幅）。
- 加入速率限制与审计日志，确保同账号在短时间内的调用频率可控。
- 实施缓存策略：优先复用 `infrastructure/cache` 中的 Redis 封装，避免重复访问 AmazingData。

### 阶段四：体验与安全加固（1 周）
- 接入微信订阅消息或模板消息，结合现有预警服务完善通知链路。
- 完成端到端安全评估：CSRF、防重放、请求签名校验。
- 在 `tests/api/miniapp` 编写集成测试，覆盖登录授权、行情查询、订阅 CRUD。
- 补充观察性指标：在 `observability` 中定义小程序 API 的延迟、错误率指标并纳入告警。

### 阶段五：灰度与上线（1 周）
- 准备灰度方案：限定白名单用户，通过配置开关控制功能曝光。
- 制定回滚指引，确保配置项可快速关闭小程序入口。
- 输出最终验收报告，确认性能测试（QPS、TP99）、安全测试以及用户体验反馈均满足要求。

## 交付物清单
- 技术评估报告、接口设计文档、配置示例与密钥管理说明。
- 小程序 API 文档（同步 `docs/api` 系列）、对应的测试用例与覆盖率报告。
- 运维 Runbook：登录异常排障、消息推送失败、缓存雪崩等应急指南。

## 风险与应对
- **微信平台限制**：及早对接企业认证与服务器域名备案，预留审批时间。
- **数据一致性**：通过缓存过期与后台回源逻辑，避免小程序与 WebUI 数据展示不一致。
- **审批节奏**：小程序端审核周期不确定，建议提前准备灰度版本与备用发布计划。
- **安全合规**：引入最小权限策略，对接微信风控告警，同时复用现有审计日志体系。

## 后续展望
- 计划在 MVP 后扩展小程序端数据看板组件，与网页版保持指标对齐。
- 预留与消息中心、运营活动系统的联动接口，为用户分层运营打基础。
- 考虑在第二阶段后着手编写自动化部署脚本，纳入 CI/CD 与静态检测。
