# 回测平台重构方案（Backtrader 集成）

## 1. 背景与动机
- 当前回测能力存在多套引擎并存、接口不统一、实时数据模拟等问题，难以支撑策略迭代与长期维护。
- Backtrader 已在工程内广泛使用，但数据适配和策略接口仍需大量手动编排，缺乏清晰的分层与测试基准。
- WebUI、API、组件层对回测的依赖持续增长，需要一个可扩展、可观测、易维护的统一平台。

## 2. 目标与衡量指标
- **统一接口**：策略、数据、任务、结果四大领域模型标准化，兼容回测与实盘（同一策略基类）。
- **可扩展性**：数据源、指标、优化算法均插件化；支持多市场、多频率及未来自研引擎接入。
- **可靠性**：构建覆盖率 ≥85%的测试矩阵，提供稳定的任务状态管理与错误告警链路。
- **可观测性**：所有回测任务具备日志、指标、性能快照；结果支持标准化导出与对比。
- **迁移友好**：保留旧流程的平滑过渡通道，确保 Web/API 在新旧版本共存期间可用。

## 3. 架构愿景
### 3.1 分层设计
1. **策略定义层**：策略 SDK、参数 Schema、指标订阅、事件钩子；统一 BaseStrategy 抽象。
2. **数据适配层**：数据桥接、字段映射、缓存、快照版本控制、数据质量校验。
3. **回测引擎层**：Cerebro 管理、撮合、风控、指标收集、任务生命周期与调度。
4. **结果服务层**：指标聚合、图表渲染、任务查询、对比分析、持久化与导出。
5. **运维支撑层**：监控、日志、限流、权限、资源管理，支持批量任务与优先级。

### 3.2 核心能力蓝图
- 插件化数据源（QMT、AkShare、CSV、自研 API），支持同步/异步拉取与缓存。
- 指标计算管线（内置 + 自定义），支持任务内动态加载与复用。
- 任务状态机（创建→排队→运行→完成/失败→归档），提供事件通知与恢复机制。
- 结果模型标准化（权益曲线、订单、成交、风险指标、日志、可视化资源）。

## 4. 模块规划
| 模块 | 说明 | 关键交付 |
| --- | --- | --- |
| 策略 SDK | 统一策略生命周期、参数校验、日志接口 | 策略基类、示例策略、开发手册 |
| 数据适配器 | 自动识别数据源、字段映射、质量校验 | DataBridge v2、缓存策略、数据诊断报表 |
| 引擎核心 | Cerebro 管理、任务执行、指标收集 | 新版 BacktestEngine、事件钩子、性能监控 |
| 任务管理 | 异步队列、优先级、批量优化 | 任务调度器、优化策略框架、对比工具 |
| 结果服务 | 指标汇总、图表、导出、API | 结果存储接口、图表渲染、WebUI 适配 |
| 运维与监控 | 日志、告警、资源配额 | Prometheus 指标、结构化日志、任务追踪 |

## 5. 分阶段实施路线
### Phase 0：准备
- 梳理现有功能依赖、数据源、策略清单，确定保留/淘汰范围。
- 输出《回测平台重构设计说明》初稿（UML、数据流、接口规范）。
- 制定迁移方案（双写 or 冷切换），完成评审与资源排期。

### Phase 1：基础内核（4~6 周）
- 实现新 `BacktestEngine` 核心，封装 Cerebro 生命周期与指标收集。
- 重写数据桥接层，提供字段标准化、缓存、快照与质量评估。
- 完成策略 SDK（参数声明、事件钩子、指标订阅）与至少 2 个示例策略。
- 建立单元/集成测试框架，覆盖数据适配、策略执行、指标统计路径。

### Phase 2：任务与服务（4~5 周）
- 构建任务状态机与异步调度，支持批量回测、参数搜索、对比分析。
- 新建结果服务：统一指标模型、图表渲染抽象、导出协议（JSON/CSV/HTML）。
- 调整 WebUI/API 以适配新接口，提供版本化文档与兼容层。
- 引入性能基准测试与资源限流，保障多任务并发稳定性。

### Phase 3：高级能力（依需求迭代）
- 接入实时/半实时行情数据，完善增量数据合并、Warm-up 机制。
- 引入策略调优框架（遗传算法、贝叶斯优化、样本外验证工具）。
- 打通回测→模拟交易流程，与事件总线、实盘风控联动。
- 增强运维：任务可视化、告警分级、自动化回归测试。

## 6. 测试与质量保障
- 构建基准数据集（多市场、多频率、极端行情）作为自动回归样本。
- 在 CI 中执行 `uv run pytest`、`ruff`、`mypy`、`bandit`，并引入覆盖率门槛。
- 关键模块提供性能测试（单任务耗时、并发吞吐、内存占用）。
- 引入对比测试工具，保证新引擎输出指标与旧版一致或明确差异原因。

## 7. 迁移策略
- 新旧引擎并行阶段启用特性开关（按模块/接口灰度），支持随时回滚。
- 提供策略/配置迁移脚本与兼容层，确保原有任务可快速切换。
- 对外接口版本化（API v1→v2），在文档中列出差异与示例。
- 与数据、前端、运维团队建立迁移清单与沟通节奏。

## 8. 风险与应对
| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 数据质量不一致 | 指标偏差、结果不可信 | 快照校验、数据诊断报表、对比测试 |
| 迁移期双写压力 | 资源消耗、调度复杂 | 分批灰度、容量评估、任务配额管理 |
| 策略接口变更 | 用户学习成本 | 提供 SDK 指南、示例、兼容适配层 |
| 实时扩展难度 | 项目拖延 | Phase 3 独立验收，确保回测核心先落地 |

1. 组织跨团队设计评审，确认本方案与资源投入。
2. 建立重构专用分支与工作板，明确负责人与交付节奏。
3. 启动 Phase 0 工作：界面梳理、文档完善、测试数据准备。
4. 搭建自动化验证基线，确保后续迭代有量化反馈。


## 附录 A：术语与缩写
| 术语 | 说明 |
| --- | --- |
| Backtrader | Python 开源回测框架，提供 Cerebro 引擎、策略、数据源等组件 |
| Cerebro | Backtrader 的核心回测执行器，负责策略运行、撮合与结果收集 |
| Adapter | 数据适配器，负责将外部数据转换为回测所需格式 |
| DataBridge | DeepSearch 内部数据桥接层，提供字段映射、数据清洗功能 |
| SDK | Software Development Kit，策略开发工具包，约束策略接口与生命周期 |
| Warm-up | 回测/实时启动时用于指标预热的数据窗口 |
| Snapshot | 数据快照，指固定时间范围内的数据副本，用于回归测试 |
| Optimization | 参数优化，指对策略参数进行网格搜索/贝叶斯等方法寻找最优组合 |

## 附录 B：接口概览（当前状态）
| 接口/模块 | 说明 | 备注 |
| --- | --- | --- |
| `GET /api/backtest/strategies` | 查询策略列表及参数信息 | WebUI 依赖 |
| `POST /api/backtest/run` | 发起回测任务 | 后台异步执行 |
| `GET /api/backtest/results/{id}` | 查询回测结果 | 包含指标、交易记录 |
| `GET /api/backtest/results/{id}/plot` | 获取回测图表 Base64 | 依赖 Matplotlib/Backtrader 绘图 |
| `POST /api/backtest/optimize` | 执行参数优化任务 | 使用 `BacktestEngine.optimize_parameters` |
| Event `BACKTEST_REQUEST` | 事件系统触发回测 | 现用旧版引擎 |
| Event `BACKTEST_QUERY` | 查询任务状态事件 | 同上 |
| `UnifiedBacktraderAdapter.get_data` | 数据拉取接口 | 支持异步/缓存 |
| `BacktestEngine.run` | 核心回测入口 | 新版引擎 |
