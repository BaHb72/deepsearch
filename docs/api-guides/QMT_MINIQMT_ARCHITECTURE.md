# QMT与MiniQMT架构差异及集成方案

> 最后更新: 2025-08-17
> 
> 本文档详细说明QMT和MiniQMT的架构差异，以及在DeepSearch系统中的集成方案。

## 架构对比

### QMT标准版架构
```
┌─────────────────────────────────────┐
│         QMT客户端（标准版）           │
│  ┌─────────────────────────────────┐│
│  │  内置Python 3.6环境              ││
│  │  策略在QMT窗口内运行             ││
│  └─────────────────────────────────┘│
│           ↓                          │
│  ┌─────────────────────────────────┐│
│  │  qmt_dynamic.py（内部脚本）      ││
│  │  通过ZMQ/Socket与外部通信        ││
│  └─────────────────────────────────┘│
└─────────────────────────────────────┘
              ↓ ZMQ/Socket
┌─────────────────────────────────────┐
│      DeepSearch系统                  │
│  接收数据并处理                      │
└─────────────────────────────────────┘
```

### MiniQMT架构
```
┌─────────────────────────────────────┐
│      MiniQMT客户端（极简模式）        │
│  开放端口供外部连接                   │
│  作为数据和交易网关                   │
└─────────────────────────────────────┘
              ↑ 本地连接
┌─────────────────────────────────────┐
│      外部Python环境（3.6-3.11）       │
│  ┌─────────────────────────────────┐│
│  │  XtQuant包                      ││
│  │  - xtdata (行情模块)            ││
│  │  - xttrader (交易模块)          ││
│  └─────────────────────────────────┘│
│           ↓                          │
│  ┌─────────────────────────────────┐│
│  │  DeepSearch系统                 ││
│  │  直接调用xtquant API             ││
│  └─────────────────────────────────┘│
└─────────────────────────────────────┘
```

## 核心差异

| 特性 | QMT标准版 | MiniQMT |
|------|-----------|---------|
| **运行环境** | QMT内置Python 3.6 | 外部Python 3.6-3.11 |
| **通信方式** | 脚本间接通信（ZMQ/Socket） | 直接API调用（xtquant） |
| **代码位置** | QMT窗口内编辑运行 | 外部IDE开发 |
| **数据获取** | 通过内部脚本中转 | 直接调用xtdata |
| **延迟** | 有通信延迟 | 延迟更低 |
| **灵活性** | 受限于QMT环境 | 完全自由 |
| **回测** | 支持 | 不支持 |
| **适用场景** | 策略开发、回测 | 实盘交易、高频 |

## 数据流对比

### QMT数据流
```
请求 → QMT内部脚本 → QMT API → 券商服务器 → 数据返回 → ZMQ推送 → DeepSearch
```

### MiniQMT数据流
```
请求 → xtquant → MiniQMT客户端 → 券商服务器 → 数据返回 → DeepSearch
```

## 集成策略

基于以上差异，我们需要为两种模式设计不同的数据提供者：

1. **QMTProvider**: 通过ZMQ与QMT内部脚本通信
2. **MiniQMTProvider**: 直接使用xtquant包调用API

两者通过统一的接口暴露给DataProviderManager，上层应用无需关心底层实现差异。
