## 1. 重复或疑似互斥的说明

### 1.1 港股通快照回调

- **文档位置**:
  - 3.5.3.3 `onSnapshotglra` (港股通实时快照)
  - 3.5.3.7 `onSnapshothkt` (港股通实时快照)
- **问题**: 两者功能描述完全一致，均为“港股通实时快照”。
- **分析**:
  - 可能是不同市场（沪港通/深港通）的区分，但文档标题未明示。
  - 可能是新旧版本的别名共存。
  - `glra` 可能代表 "Global/General"? `hkt` 代表 "Hong Kong Connect"?
- **建议**: 在代码实现时需确认两者的区别，文档中暂标记为“功能重叠/疑似别名”。

## 2. 模块分类不一致

### 2.1 证券基础信息类接口

- **接口**:
  - `get_stock_basic` (证券基础信息)
  - `get_history_stock_status` (历史证券信息)
  - `get_bj_code_mapping` (北交所新旧代码对照)
- **文档归属**: PDF 第 3.5.2 节 **基础数据 (BaseData)**
- **旧清单归属**: InfoData 模块
- **影响**: 开发者如果按照旧清单在 `InfoData` 类中寻找这些方法，可能会找不到（如果代码遵循文档结构）。
- **建议**: 将这些接口在 API 清单中移至 **BaseData** 模块，以保持与 PDF 手册结构一致。

## 3. 枚举值说明更新

### 3.1 security_type

- **旧说明**: "28种类型"
- **新文档 (4.1.1)**:
  - 包含 `EXTRA_STOCK_A`, `SH_A`, `SZ_A`, `BJ_A` 等基础类型。
  - 新增了 `EXTRA_KZZ` (可转债), `EXTRA_ETF_OP` (期权), `EXTRA_FUTURE` (期货) 等大类。

- **建议**: 不再硬编码“28种”，而是建议“参考 PDF 附录 4.1 代码类型表”，因为随着业务扩展，类型数量会动态增加。

## 4. 总结

文档中主要存在 **分类归属** 和 **接口别名** 两类一致性问题。更新后的 `api_inventory.md` 将采用 PDF 的章节结构（BaseData/InfoData/MarketData/SubscribeData）作为唯一真理来源进行重组。
