# strategies 模块实现说明

## 模块定位

`deepsearch.strategies` 汇集策略框架、模板与具体实现，承担策略生命周期管理、信号生成与风险控制。模块把策略看作组件，与事件引擎、数据管道、交易网关协作。

## 目录结构

- `interfaces/`：定义策略基类、信号接口、风险控制抽象。
- `implementations/`：内置策略示例与参考实现。
- `managers/`：策略编排与调度器，负责装载、热更新、回滚。
- `services/`：策略运行时依赖（如风控检查、仓位管理、绩效分析）。
- `events/`：策略专用事件与订阅封装。

## 核心数据结构

- `StrategyContext`：记录账户、持仓、参数与运行状态。
- `Signal`/`OrderIntent`：策略输出的标准结构，兼容 `event` 与 `gateway`。
- `RiskRule`：定义校验逻辑及对应的处理动作（拒单、降档等）。

## 关键流程

1. 管理器读取配置，动态加载策略类并创建 `StrategyContext`。
2. 通过 `event` 模块订阅行情/系统事件，调用策略的 `on_event` 生成信号。
3. `services` 中的风控/仓位服务对信号进行校验与转换。
4. 合规信号转换为 `messaging` 消息，最终流向 `gateway` 下单。
5. 运行中支持热更新：策略文件变更后可触发重新加载并回滚旧版本。

## 扩展与集成

- 新策略需继承基础接口，并在 `settings.strategy` 中注册别名。
- 若引入外部模型，可通过依赖注入容器提供服务，避免直接引用第三方库。
- 风控规则扩展应在 `services/risk` 下实现，确保可配置化。
- 回测与实时共用同一策略接口，注意不要在策略内引用环境特定的 API。
